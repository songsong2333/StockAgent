# A股量化系统 · 桌面应用构建指南

把项目打包成**跨平台桌面应用**：Mac 双击运行的 `.app`、Windows 的 `.exe`。
打包后是**自包含**的——接收方无需安装 Python 或任何依赖，双击即用。

> 技术栈：pywebview（原生窗口包裹 Streamlit）+ PyInstaller（onedir 打包）。
> 入口：`app/desktop_app.py`；打包配置：`build/stock_agent.spec`。

---

## 1. 前置条件

### Mac
| 项 | 说明 |
|---|---|
| Python 3.9+ | 项目 `.venv` 即可 |
| libomp | `brew install libomp`（lightgbm 动态库依赖，**不装会崩**） |
| 依赖包 | `pip install -r requirements.txt`（已含 pyinstaller/pywebview/platformdirs） |

### Windows
| 项 | 说明 |
|---|---|
| Python 3.11 | qlib 0.9.7 官方支持到 3.10，3.11 社区验证可行；**避免 3.12** |
| 依赖包 | `pip install -r requirements.txt` |
| WebView2 | Win10 1803+ / Win11 自带，无需额外装 |

## 2. 构建 Mac 应用（`.app`）

```bash
# 1) 装依赖（含打包工具）
brew install libomp
pip install -r requirements.txt

# 2) 打包
pyinstaller build/stock_agent.spec --noconfirm
```

> ⚠️ 用 `.spec` 文件时**不要加** `--windowed` / `--noconsole` 等参数——窗口模式已写在 spec 里（`console=False`），加了会报错 "option(s) not allowed"。

产出：
```
dist/
├── A股量化系统.app        ← 双击运行的这个（Mac app bundle）
└── A股量化系统/           ← onedir 目录（.app 的内容来源，可忽略）
```

### 2.1 架构说明
本机构建出的 `.app` 是**当前 CPU 架构**：
- Apple Silicon（M 芯片）Mac 上构建 → `arm64`，**只 M 芯片能跑**。
- Intel Mac 上构建 → `x86_64`，只 Intel 能跑。

绝大多数现代 Mac 是 M 芯片。如要同时覆盖 Intel，需在 Intel Mac 上另出一份。

### 2.2 验证构建是否成功
```bash
open "dist/A股量化系统.app"
```
弹出原生窗口、能正常显示五个页面即成功。

**进阶验证（确认 app.py 脚本本身能跑通，不只是外壳）**：
应用启动后会监听一个随机端口。找到端口后请求脚本健康检查端点，应返回 `ok`：
```bash
PORT=$(lsof -nP -iTCP -sTCP:LISTEN -a -p $(pgrep -f stockagent-serve | head -1) | awk 'NR>1{print $9}' | sed 's/.*://' | head -1)
curl "http://127.0.0.1:$PORT/_stcore/script-health-check"   # 应输出 ok
```
> 只 curl `/` 返回 200 **不代表**脚本跑通（外壳加载成功但脚本可能报错），务必用 `script-health-check`。

### 2.3 重新签名（本地可跑）
PyInstaller 已自动做 ad-hoc 签名。若本机双击提示无法打开，手动签：
```bash
codesign --force --deep --sign - "dist/A股量化系统.app"
xattr -dr com.apple.quarantine "dist/A股量化系统.app"
```

## 3. 构建 Windows 应用（`.exe`）

**Mac 打不出 Windows `.exe`**（PyInstaller 不能跨平台）。两种方式：

### 方式 A：GitHub Actions（推荐，无需 Windows 机器）
已配置 `.github/workflows/build-windows.yml`：

1. 把代码 push 到 GitHub。
2. 进入仓库 **Actions** 标签页 → 左侧选 **「Build Windows EXE」** → 右上 **Run workflow** → 选分支运行。
   - 或打个 `v` 开头的 tag（如 `v1`）推送，会自动触发。
3. 等构建完成（约 5–10 分钟）→ 进入该次运行 → 拉到底 **Artifacts** 区下载 `stock_agent-windows.zip`。

### 方式 B：在 Windows 机器上本机构建
```powershell
pip install -r requirements.txt
pyinstaller build\stock_agent.spec --noconfirm
```
产出 `dist\A股量化系统\A股量化系统.exe`。

## 4. 分发给他人

打包物**自包含**，对方无需装 Python。但两个平台都有系统安全拦截：

### Mac（最需要注意）
ad-hoc 签名 + **未公证**，对方收到（尤其经压缩/下载）大概率弹：
> 「A股量化系统」已损坏，无法打开。/ 无法验证开发者。

**不是真坏**，两种处理：
- **让对方在终端跑**（最简单）：
  ```bash
  xattr -cr "/Applications/A股量化系统.app"
  ```
  然后双击即可。
- **正式分发（零摩擦）**：用 Apple Developer ID 签名 + `notarytool` 公证（需 $99/年开发者账号）。公证后对方双击直接能开。

> 传输前建议压成 zip：`cd dist && zip -r A股量化系统-mac.zip "A股量化系统.app"`

### Windows
未签名 `.exe` 首次运行会被 **SmartScreen** 拦一下，点 **「更多信息」→「仍要运行」** 即可。个人/内部用足够。正式分发需购买代码签名证书。

## 5. 运行时数据位置
打包后，配置和采集的数据**不在程序目录**，而在用户数据目录（首次运行自动从内置模板拷配置）：
- **Mac**：`~/Library/Application Support/stock_agent/`
- **Windows**：`%LOCALAPPDATA%\stock_agent\StockAgent\`

想让对方「清空重来」或迁移数据，动这个目录即可。

---

## 6. 开发模式（不打包，直接跑）
改代码调试时不必每次打包，源码模式即可打开原生窗口：
```bash
python app/desktop_app.py
```
此模式下路径仍指向项目根目录（与打包后的用户目录不同），方便开发。

---

## 7. 改了代码后重新打包
直接重跑打包命令即可，会覆盖 `dist/`：
```bash
pyinstaller build/stock_agent.spec --noconfirm
```
> 改 `app/app.py`、`common.py`、`strategy/`、`collector/` 等任何业务代码后都要重打包才生效（打包是把代码冻结进 bundle 的快照）。

## 8. 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `--windowed makespec options not valid` | `.spec` 模式下不要传 `--windowed`，去掉即可 |
| Mac 打开后应用内红字 `ModuleNotFoundError: strategy/...` | spec 顶部的 `sys.path.insert(0, ROOT)` 不能删——少了它 `collect_submodules` 收不到项目包 |
| Mac 打开后白屏 / 404 页 | spec 里 `global.developmentMode=False` 和 `get_static_dir` patch 不能删（见 `app/desktop_app.py` `_run_server`） |
| lightgbm `Library not loaded: libomp` | Mac 没装 libomp → `brew install libomp` 后重新打包 |
| 体积大（~430MB） | 正常：streamlit + qlib + lightgbm + pandas/numpy 全量打包 |
| 打包慢（1–2 分钟） | 正常：`collect_all` 要收集多个重依赖 |
| 双进程 / 端口 | 架构是「父进程跑窗口 + 子进程 `--serve` 跑 streamlit」，属正常设计 |
